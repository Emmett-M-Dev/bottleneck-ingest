## Global Constraints

- **Backend is a thin orchestrator.** It shells out to the pipeline venv via the existing `_run_pipeline` helper. It must not import `simulator`, `pandas`, `chromadb`, `pyarrow` or `torch` — the api venv is separate and py3.14.
- **Every subprocess call goes through `_run_pipeline`** (`api/main.py:37-55`). It already sets `PYTHONIOENCODING=utf-8` and `encoding="utf-8"`, which is mandatory: SME status columns contain `✔` and `text=True` alone decodes with the Windows ANSI codepage and dies.
- **Design tokens come from `src/constants.js`.** Every component reads `C.*`. Never hardcode a hex value. Available: `C.NAVY`, `C.NAVY2`, `C.INK`, `C.MUTED`, `C.TEAL`, `C.TEAL_D`, `C.TEAL_L`, `C.GREEN`, `C.GREEN_L`, `C.AMBER`, `C.AMBER_L`, `C.RED`, `C.RED_L`, `C.BG`, `C.SURFACE`, `C.LINE`, `C.LINE_2`.
- **Follow the existing component idiom:** function components, no TypeScript, Tailwind utility classes for layout, inline `style={{ }}` for anything colour-related so it reads from `C`.
- **The simulator writes to `data/sim/<profile>/`** in the pipeline repo. The backend never writes there itself — only the CLI does.
- **Demo mode shows simulated data in the real dashboard.** That is the point, and it means the shared `outputs/event_log.parquet` holds simulated advisory data while demo mode is active. A persistent banner must say so, and a restore action must exist (Task 8).
- Windows: the pipeline venv is `bottleneck-ingest/.venv/Scripts/python.exe`, already resolved as `_PIPELINE_PY`.

## Testing approach — a stated deviation

`hitl-react` has **no test infrastructure**: no vitest, no API tests, no test files. Adding a full frontend test harness is larger than this feature and is not in this plan.

So the split is:

- **Backend gets real TDD.** Tasks 1-3 add `pytest` + `httpx` to `api/requirements.txt` and TDD every route. The backend carries the correctness risk here — the owner-stamp comparison, subprocess wiring, JSON shapes.
- **Frontend gets explicit manual verification.** Tasks 4-8 end with exact commands to run and exactly what you should see on screen. These are written as checkable observations, not "check it looks right". A visual feature's correctness genuinely is "does the right thing happen on screen", and a snapshot test would not answer it.

Do not write a frontend test that asserts nothing meaningful in order to satisfy a TDD shape.

### Task 1: Stop the dashboard wiping the simulated world

**This is blocking. Demo mode is impossible without it, and it is not obvious.**

P1 made `ingest.py` stamp the event-log owner as `f"{profile}@{drive}"` when `--drive` is passed, so a simulated ingest is distinguishable from a real one. But `api/main.py:203-209` reads that marker raw, and `api/main.py:237` compares it exact-equal to the profile:

```python
if _event_log_owner() != profile:
    ingest = _run_pipeline("ingest.py", "--source", "messy", "--profile", profile, ...)
```

With the marker reading `advisory@data/sim/advisory/drive` and `profile` being `advisory`, that comparison fails on **every** action-queue fetch. The dashboard would silently re-ingest the static drive and destroy the simulated world, repeatedly, while the user watches. The pipeline repo already fixed the equivalent comparison in `bridge/export_actions.py` by splitting on `@`; this is the same fix in the other repo.

def _event_log_profile() -> str | None:
    """The profile part of the event-log stamp.

    `ingest.py --drive <path>` stamps `<profile>@<drive>` so a run against an
    alternate drive — a simulator drive, or a later snapshot for outcome
    measurement — is distinguishable from a run against the static drive.
    Callers deciding *whose* data this is want the profile alone; comparing
    the full stamp would re-ingest on every request and destroy that data.

    owner = _event_log_owner()
    return owner.split("@", 1)[0] if owner else None

# ── Simulator (demo mode) ────────────────────────────────────────────────────
# The world simulator lives in the pipeline repo and owns its own state under
# data/sim/<profile>/. This API only drives it, exactly as it drives ingest and
# the action CLI: one shell-out, one JSON object back.

_TIMEOUT_SIM = 300


def _run_sim(profile: str, *args: str) -> dict:
    proc = _run_pipeline("-m", "simulator.cli", "--profile", profile, *args,
                         timeout=_TIMEOUT_SIM)
    if proc.returncode != 0:
        raise HTTPException(
            status_code=500,
            detail=f"simulator failed: {(proc.stderr or proc.stdout)[-400:]}")
    try:
        return json.loads(proc.stdout)
    except (json.JSONDecodeError, TypeError):
        raise HTTPException(
            status_code=500,
            detail=f"simulator produced no JSON: {(proc.stdout or '')[-400:]}")


@app.get("/api/sim/{profile}/status")
def sim_status(profile: str):
    """Where the simulated world currently stands. Does not advance it."""
    _require_profile(profile)
    return _run_sim(profile, "--status")


@app.post("/api/sim/{profile}/reset")
def sim_reset(profile: str):
    """Rebuild the world at day 0 and render the drive. Clears the inbox."""
    _require_profile(profile)
    return _run_sim(profile, "--reset")


@app.post("/api/sim/{profile}/advance")
def sim_advance(profile: str, req: SimAdvanceRequest):
    """Advance N sim days. Approved action items are read from the action
    store by the CLI and change what the simulated staff do."""
    _require_profile(profile)
    args = ["--advance", str(req.days)]
    if req.llm:
        args.append("--llm")
    return _run_sim(profile, *args)

### Task 5: The clock hook

**Files:**
- Create: `src/hooks/useSimClock.js`

**Interfaces:**
- Consumes: `getSimStatus`, `resetSim`, `advanceSim`, `getSimDrive` from Task 4.
- Produces: `useSimClock(profile, { onWeekBoundary })` returning
  `{ day, date, cases, running, messages, changedRows, sheets, error, start, pause, reset, stepOnce }`.
  - `messages` — every message so far, newest first, each `{ ...message, revealed: bool }`.
  - `changedRows` — a `Set` of case ids touched on the most recent day, for the grid's flash.
  - `start()` / `pause()` toggle autoplay; `stepOnce()` advances exactly one day; `reset()` returns to day 0.
  - `onWeekBoundary(day)` is called after any advance where `day % 7 === 0`.

The day is the unit of truth and commits atomically in the backend. The drip is presentation only: the hook reveals the day's already-committed messages one at a time on a timer, then moves on. Nothing downstream ever sees a half-applied day.

- [ ] **Step 1: Write the hook**

Create `src/hooks/useSimClock.js`:

```javascript
import { useCallback, useEffect, useRef, useState } from 'react'
import { advanceSim, getSimDrive, getSimStatus, resetSim } from '../api/client.js'

// Pace: one sim day every DAY_MS, with that day's messages revealed one at a
// time DRIP_MS apart. Slow enough to narrate, fast enough that a week passes
// while someone is still watching.
const DAY_MS = 2600
const DRIP_MS = 700

export function useSimClock(profile, { onWeekBoundary } = {}) {
  const [day, setDay] = useState(0)
  const [date, setDate] = useState('')
  const [cases, setCases] = useState(0)
  const [messages, setMessages] = useState([])
  const [changedRows, setChangedRows] = useState(new Set())
  const [sheets, setSheets] = useState([])
  const [running, setRunning] = useState(false)
  const [error, setError] = useState(null)

  const busy = useRef(false)
  const timer = useRef(null)
  const boundary = useRef(onWeekBoundary)
  boundary.current = onWeekBoundary

  const loadDrive = useCallback(async () => {
    try {
      const d = await getSimDrive(profile)
      setSheets(d.sheets || [])
    } catch (e) {
      setError(String(e))
    }
  }, [profile])

  const applyDay = useCallback((result) => {
    const incoming = (result.messages || []).map(m => ({ ...m, revealed: false }))
    setMessages(prev => [...incoming, ...prev])
    setChangedRows(new Set(result.row_changes || []))
    // Reveal them one at a time so the sidebar reads like an inbox filling up,
    // not a batch landing. State is already committed either way.
    incoming.forEach((m, i) => {
      setTimeout(() => {
        setMessages(prev => prev.map(
          x => x.msg_id === m.msg_id ? { ...x, revealed: true } : x))
      }, DRIP_MS * (i + 1))
    })
  }, [])

  const stepOnce = useCallback(async () => {
    if (busy.current) return
    busy.current = true
    try {
      const res = await advanceSim(profile, 1)
      setDay(res.day)
      setDate(res.date)
      setCases(res.cases)
      ;(res.days || []).forEach(applyDay)
      await loadDrive()
      if (res.day % 7 === 0 && boundary.current) boundary.current(res.day)
      setError(null)
    } catch (e) {
      setError(String(e))
      setRunning(false)
    } finally {
      busy.current = false
    }
  }, [profile, applyDay, loadDrive])

  const reset = useCallback(async () => {
    setRunning(false)
    try {
      const res = await resetSim(profile)
      setDay(res.day)
      setDate(res.date || '')
      setCases(res.cases)
      setMessages([])
      setChangedRows(new Set())
      await loadDrive()
      setError(null)
    } catch (e) {
      setError(String(e))
    }
  }, [profile, loadDrive])

  // Autoplay. One in-flight advance at a time — busy guards against a slow
  // backend queueing days behind each other.
  useEffect(() => {
    if (!running) return undefined
    timer.current = setInterval(stepOnce, DAY_MS)
    return () => clearInterval(timer.current)
  }, [running, stepOnce])

  // Pick up wherever the simulated world already is.
  useEffect(() => {
    let alive = true
    getSimStatus(profile)
      .then(s => {
        if (!alive) return
        setDay(s.day); setDate(s.date || ''); setCases(s.cases)
      })
      .catch(e => alive && setError(String(e)))
    loadDrive()
    return () => { alive = false }
  }, [profile, loadDrive])

  return {
    day, date, cases, running, messages, changedRows, sheets, error,
    start: () => setRunning(true),
    pause: () => setRunning(false),
    reset, stepOnce,
  }
}
```

import { C } from '../../constants.js'

export default function SheetGrid({ sheets, changedRows }) {
  const [active, setActive] = useState(0)

  // A sheet list that shrinks (a reset, a profile switch) must not leave the
  // tab index pointing past the end.

      <div className="flex gap-1 px-2 pt-2 overflow-x-auto"
           style={{ borderBottom: `1px solid ${C.LINE}` }}>

                  style={i === active
                    ? { background: C.TEAL_L, color: C.TEAL_D }

            {s.name}
          </button>
        ))}

          <thead className="sticky top-0" style={{ background: C.BG }}>

              ))}

              const touched = changedRows.has(row[0])

                      {cell}
                    </td>
                  ))}

// The RAG grounding: past resolutions the diagnosis agent retrieved, with how
// similar each was. This is the answer to "why is it telling me this?", so it
// belongs next to the recommendation rather than on a separate screen.
function Grounding({ resolutions }) {
  if (!resolutions?.length) return null
  return (
    <div className="mt-3">
      <div className="text-[11px] font-semibold mb-1.5" style={{ color: C.MUTED }}>
        🧠 Grounded in {resolutions.length} past resolution
        {resolutions.length !== 1 ? 's' : ''}
      </div>
      <div className="space-y-1.5">
        {resolutions.map((r, i) => (
          <div key={r.resolution_id ?? i} className="rounded px-2.5 py-1.5"
               style={{ background: C.LINE_2 }}>
            <div className="flex items-center gap-2">
              <span className="text-[10px] font-mono" style={{ color: C.MUTED }}>
                {(r.resolution_id ?? r.source ?? '').replace('corpus:', '')}
              </span>
              <span className="text-[10px] ml-auto font-semibold"
                    style={{ color: C.TEAL_D }}>
                {Math.round((r.similarity_score ?? 0) * 100)}% similar
              </span>
            </div>
            {r.text && (
              <p className="text-[11px] mt-1" style={{ color: C.INK }}>{r.text}</p>
            )}
          </div>
        ))}
      </div>
    </div>
  )
}
